## Условия и воспроизведение

Запуск: отдельный headless Chrome, стандартный mobile-профиль Lighthouse и официальный `desktop-config.js`. Параметры throttling не переопределены. Mobile: 412 × 823 CSS px, DPR 1,75; desktop: 1350 × 940 CSS px, DPR 1. Измерение проводится с очищенным состоянием Lighthouse, без специально прогретого кэша. Локальная среда Node.js 25.9.0; проект и CI настроены на Node.js 24.

В одном терминале:


## Что обеспечивает результат

- Статический HTML Astro, обычный CSS и небольшой TypeScript-модуль; клиентский UI-фреймворк не нужен.
- Адаптивные AVIF/WebP с реальными размерами и `sizes`; hero загружается приоритетно, нижние изображения — лениво.
- Локальные WOFF2 Golos Text и Playfair Display, подмножества около 62 КБ суммарно; без запросов к внешнему сервису шрифтов.
- Зарезервированные размеры изображений, отсутствие сдвигов при загрузке.
- Библиотечные SVG-иконки, без отдельного icon-font и сторонних виджетов.
- Исходные PNG, промпты и дополнительные городские кадры не попадают в загрузку главной.

В ходе оптимизации mobile Performance вырос с 95 до 100. Перепроверены качество изображений, читаемость и визуальное соответствие референсу. Контраст и доступное имя кнопки подборки исправлены; аудит `label-content-name-mismatch` проходит в обоих профилях.

## Практические пределы

Это лабораторный результат локальной production-сборки, **не результат публичного PageSpeed Insights**. Публичная версия ещё не развёрнута. DNS, TLS, задержка хостинга, регион тестирования и последующие сторонние скрипты могут изменить результат. После публикации нужно повторить аудит домена; полевые Core Web Vitals появятся только при достаточном реальном трафике.

Lighthouse сохраняет информационные рекомендации по дополнительному сжатию и размерам отдельных изображений. Текущие оценки 100/100 не означают отсутствие любых рекомендаций или гарантированное место в поиске. Выбранное качество проверено визуально.
