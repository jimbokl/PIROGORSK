# Проверки калькулятора и IndexNow

Дата: 24.10.2026. Концепция: калькулятор для семейного стола, балтийская бумажная палитра, крупный итоговый вес. Две колонки на широком экране, одна на телефоне; существующие Golos/Playfair, морской тёмный, тёплый акцент. Контролы без декоративной анимации. Основной визуальный элемент — послойный пирог и крупное значение кг.

## Проверено локально

- Astro/TypeScript: 0 errors/warnings/hints, 51 файл. Build: 24 HTML; SEO: 7 продуктов, 22 URL sitemap, 1671 локальная ссылка.
- 10 Node tests: IndexNow (6), формула/округление/цены/URL-параметры калькулятора (4). Перебраны все поддерживаемые сочетания числа гостей, порции и 1–3 начинок. Фактический вес не меньше заданного; превышение меньше 500 г.
- UI на `127.0.0.1:4322/podbor/`: 4 × 300 г → 1,5 кг, мясо 1 кг + капуста 500 г, 1680 ₽. Затем 10 × 300 г, мясо/рыба/капуста → 3 кг, по одному пирогу 1 кг, 3470 ₽.
- Выбран Калининград; переход открыл подборку с этим городом. Предыдущие сыр 500 г/мясо 500 г/морс сохранились, уже выбранная рыба 1 кг не продублировалась. Reload оставил те же количества и сумму. Форму в этом тесте не отправляли, новых QA-заявок нет.
- Канонический manifest создаётся только из sitemap; `/privacy/`, `/terms/` и URL с параметрами не включены.

## Ограничения доказательств

Публичные HTTP 200/202 IndexNow и CI-публикация фиксируются отдельно после deploy. Это уведомление, не подтверждение индексации. Сохранение state зависит от GitHub Actions cache: при его удалении/вытеснении следующий запуск заново отправит все канонические URL один раз. Неизменное состояние проверяется тестом без HTTP.

Результат PSI 100/100 от 16:12 относится к предыдущей опубликованной главной; он не является измерением новой страницы `/podbor/`.
