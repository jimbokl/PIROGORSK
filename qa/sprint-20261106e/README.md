## QA-17: промах физического клика в CI

CI [42278373258](https://github.com/jimbokl/PIROGORSK/actions/runs/42278373258)
не публиковал сборку: check/build/content/unit/Worker прошли, browser упал
на четвёртом добавлении на главной 320 px. Исходные JSON/PNG сохранены
в `ci-failure/`, полный вывод — `logs/ci-failed.log`.

Pointerdown/up/click пришлись на INPUT количества: x=160, y=458.39.
После клика кнопка была x=35, y=475.20, width=235 (центр 152.5/498.20).
На macOS без полосы прокрутки тот же сценарий даёт width=250 и центр
160/458.39. Сбой — промах физического указателя; обработчик добавления
при этом не вызывался. Screenshot также показал соседнюю карточку.

В Puppeteer 25.16 element.screenshot по умолчанию использует CDP
captureBeyondViewport=true. [Исходник Chromium](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/browser/devtools/protocol/page_handler.cc)
в этом пути выставляет hide_scrollbars=true, меняет device emulation,
потом восстанавливает параметры. Это объясняет наблюдаемые 15 px разницы
и является основной проверяемой причиной рассинхронизации. Детерминированного
локального промаха не получили: 3 CPU×4 прогона без полосы и 3 с полосой
прошли; ещё 5 исходных с полосой также PASS. Это не доказательство устранения.

Изменение ограничено тестом: для снимка карточки captureBeyondViewport=false,
то есть текущая область экрана без временного скрытия scrollbar. Центровка,
locator, реальное нажатие и точное сравнение всех строк подборки сохранены.
Не добавлялись повторный клик, element.click или ослабление assert. В failure
JSON добавлен clientWidth. Продуктовый код каталога не менялся.

Повторяемый сценарий с полосой 15 px, как в CI:

```sh
QA_WIDTHS=320,390,1280 QA_ITERATIONS=2 QA_CPU=4 node qa/sprint-20261106e/reproduce-click.mjs
```

Локальный повтор после изменения: 6/6 PASS при CPU×4 и полосе 15 px
на 320/390/1280 px; 84 точных сравнения подборки, 30 товарных просмотров.
[Краткий результат](click-regression-summary.json). Исходный тест с полосой
до изменения также дал 5/5 PASS; поэтому локальный A/B не доказывает
устранение редкого промаха. Повторный CI и production-приёмка прошли.

Полный `npm run test:browser` после изменения: PASS (`logs/browser-fixed.log`).

### Ошибка декодирования изображения

Первый production content-прогон остановился на `img.decode()` с
EncodingError после первых шести статей. Конкретный URL в исходном
исключении не указан; `logs/content-production-first-failure.log` сохранён.
Дополнительная обвязка [diagnose-content-images.mjs](diagnose-content-images.mjs)
сохранила исходные assert/decode и добавила только сведения о запросах
и изображения при повторной ошибке. Этот полный прогон прошёл; затем
исходный `scripts/verify-content-month.mjs` также прошёл все 145 просмотров.

В диагностическом прогоне зафиксированы отмены запросов responsive AVIF
при смене размеров/навигации и один ERR_SSL_PROTOCOL_ERROR старого изображения
`piknik-s-pirogom-chto-vzyat`, при этом все три выбранных изображения
каждой статьи успешно декодировались. [События](content-production-diagnostic-report.json).
Отмены не объявляются причиной первого EncodingError: это не доказано.
Три самостоятельных GET того старого AVIF дали HTTP 200, одинаковые байты
и успешное декодирование 800×533. Кодирование отличается от локального
файла; причина различия не установлена, byte-identity PASS для него
не заявляется. [Readback](image-request-readback.json), [полученный файл](image-request-live.avif).
Исходная ошибка остаётся в наблюдениях QA-17; новый runtime не менялся,
автоматические повторные попытки в verifier не добавлялись.
