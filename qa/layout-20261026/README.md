## Изменение и причина

Проверяемая страница: `/journal/dostavka-edy-v-zelenogradske/`. Базовый runtime `e4f5bf4`, последний публичный PSI `1eu8qmvnk3`: P89 mobile / P98 desktop, CLS 0.09 / 0.088.

В контролируемом локальном опыте загрузка WOFF2 задержана на 2000 мс; картинки и остальной HTML не менялись. Observer фиксировал layout-shift без recent input. На 390 px хлебные крошки при смене шрифта становились на 16 px выше и сдвигали статью. На 1350 px менялась балансировка H1. Третьему или последующему текущему пункту крошек на mobile выделена отдельная строка; короткие двухпунктные крошки блога остаются в одну строку. Для H1 статьи отключена балансировка строк (`text-wrap:wrap`). Полный заголовок сохраняется в DOM и H1, длинный текущий пункт крошек может быть сокращён многоточием.

JSON опытов сохранены здесь; промежуточные `wrap-only-*` показывают, почему одного H1 было недостаточно для mobile. Нормальный UI проверен на 320 / 390 / 1280 px, снимки `ui-*.png`; горизонтального переполнения не обнаружено.

## Измерение спроса

`src/lib/analytics-session.ts` исключает localhost/preview и явно отмеченную QA-сессию. На production открыть URL с `?qa=1`: счётчик не загружается, просмотры и цели не отправляются. Флаг sessionStorage сохраняет исключение при переходах в той же вкладке. Обычный посетитель production без флага продолжает учитываться. Если браузер блокирует sessionStorage, исключена только явно отмеченная страница; для переходов тогда также использовать `qa=1`.

Это исключение Метрики, не backend: отправленная форма по-прежнему создаёт D1-запись. Для таких тестов сохранять UUID и исключать отдельно. Этот проход не создавал заявок. Ранее накопленные QA-визиты автоматически не очищаются. Новая вкладка может наследовать storage от opener; возвращение к обычному учёту проверять в чистой сессии.
