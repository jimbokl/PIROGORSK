# Трафик и проверка спроса

Обновлено 24.10.2026. Цель: привести людей на pirogorsk.ru и измерить сохранённое анонимное намерение. Производство и продажи пока не запущены. Бюджет — домен/хостинг и несколько размещений в Telegram; heartbeat не нужен.

## Сделано по новому плану

- Новый этап: цель 100 реальных посетителей в день и SEO-блог. `/blog/` объединяет семь материалов; три новые статьи с авторскими AI-иллюстрациями отвечают на вопросы количества, формата и напитков. План: [BLOG-PLAN.md](BLOG-PLAN.md). До публикации Метрика за 24.10 показывает 7 посетителей/8 прямых визитов, без отделения QA; это ещё не реальный поисковый поток.

- `/podbor/`: калькулятор веса и предварительной стоимости. Число гостей 1–30, порция 100–500 г с шагом 50 г, 7 начинок, 3 города. Формула видима: гости × заданная посетителем порция → округление вверх до 500 г. Два одинаковых полкилограммовых варианта объединяются в 1 кг. Размер порции — изменяемое допущение, не рекомендация по питанию.
- Перенос результата в существующую подборку с проверкой товаров/размеров/количества. Сохраняет предыдущий выбор; повторный переход не увеличивает количество повторно. Сама работа калькулятора не сохраняет заявку и не вызывает `order_submit`.
- IndexNow после публикации: хеши канонического HTML из sitemap; новые, изменённые и удалённые URL одним пакетом в один endpoint. Перед отправкой проверяются ключ и manifest именно на публичном домене. Кэш подтверждённых хешей обновляется только после HTTP 200/202. Неизменные страницы повторно не отправляются.

- `/povody/` и шесть отдельных сценариев из исходного плана: офисный день рождения, фуршет, поминальный стол, обед для бригады, подарок семье после выписки, встреча в бане. Каждый содержит самостоятельный чек-лист и свой изменяемый пресет калькулятора. Контент и параметры разделены в типизированных данных; новый сценарий автоматически попадает в маршруты и sitemap. Проверяются уникальность slug и соответствие пресетов реальному каталогу.

- Первый гид `/journal/gde-poest-v-zelenogradske/` опубликован: 2 кафе, 4 цены, официальные меню и дата, расчёты на четверых, переход в калькулятор. Без утверждения среднего чека или равной сытности разных блюд. [QA](qa/food-guide-20261024.md).
- Подготовлены два объявления и разные фиксированные UTM для Telegram: [TELEGRAM-TEST.md](TELEGRAM-TEST.md). Никаких размещений/оплат пока нет.

## Следующая последовательность

1. После восстановления инструмента Яндекса отправить `https://pirogorsk.ru/sitemap.xml` в подтверждённом свойстве и прочитать результат независимо. Сейчас официальный интерфейс запрещает добавление в режиме «Только для чтения». Обход по Метрике также временно недоступен; привязка счётчика не подтверждена.
2. Расширять полезные сценарии отдельными страницами, когда можно дать самостоятельный ответ: сколько еды на семейный ужин, как разделить сытное и сладкое, что проверить в апартаментах перед ужином. Связать с калькулятором и каталогом. Не размножать одну страницу под десятки формулировок.
3. Дополнять первый гид свежими меню: цена, вес при наличии, источник и дата. Не выдавать набор разных блюд за средний чек или равноценные порции; окончательная стоимость нашего предложения пока не утверждена.
4. Для двух подготовленных Telegram-размещений выбрать релевантные каналы и сравнить фактические условия. Публикация/оплата требуют конкретного выбранного канала и бюджета. Измерять переход → просмотр меню → подборка → открытие/начало формы → успешное сохранение. Не путать клики с сохранённой заявкой.
5. По фактическим GSC/Яндекс/Метрика данным дополнять страницы, на которые уже есть показы. Сверять `order_submit` с D1, исключая три QA UUID из ANALYTICS.md. Нулевой спрос при малом или нерелевантном трафике ещё не опровергает продукт.

## Что из исходного плана пока не имеет основания

- 200–300 страниц, 100 посетителей в день и CTR 8–12% — гипотезы, а не прогноз по собранным данным. Цель по количеству страниц не заменяет полезность.
- Нет подтверждённых маршрутов/времени доставки для микрорайонов, точных калорий, утверждённой рецептуры или соотношения теста/начинки. Их нельзя переносить в страницы, OG и schema как факты.
- Счётчики «осталось 3 слота», отзывы о несуществующих заказах и массовые сообщения от имени клиентов не подходят текущему этапу.
- Google Indexing API предназначен для JobPosting и определённых BroadcastEvent/VideoObject, а не для товарных страниц пирогов. Для Google уже используется sitemap в Search Console.
- Worker API заявок не обслуживает HTML на GitHub Pages. Его журнал запросов не доказывает обход HTML поисковыми роботами.
- Карточки реальной пекарни в справочниках — после выбора действующего бизнеса и выполнения требований площадки.

## Основания

- [IndexNow documentation](https://www.indexnow.org/documentation): пакет до 10 000 URL, проверка ключа, коды ответа. HTTP 200 — принятие уведомления, 202 — принятие с ожидающей проверкой ключа; ни один не подтверждает индексацию.
- [IndexNow FAQ](https://www.indexnow.org/faq): уведомления передаются участвующим поисковикам; повторять один пакет отдельно в каждый endpoint не нужно.
- [Google Indexing API](https://developers.google.com/search/apis/indexing-api/v3/quickstart): допустимые типы страниц.
