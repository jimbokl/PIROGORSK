# Пирогорск

Статический сайт на Astro: пироги с балтийским характером. Зеленоградск, Калининград и Светлогорск; восемь начинок, 500 г / 1 кг, напитки и дополнения — всего 14 товаров. Подборка с количеством, суммой и копированием, сохранение города и выбора в браузере. 69 HTML-страниц (67 URL в sitemap): каталог, города, продукты, сценарии и статьи. Нативные модальные окна, адаптивная сетка, клавиатурная навигация.

Проект проверяет спрос до открытия: цены и изображения предварительные. Анонимная форма сохраняет намерение заказать через Cloudflare Worker + D1, без имени и контактов. Оплата и подтверждённые заказы пока не принимаются. HTTPS на pirogorsk.ru работает; очередная публикация и проверки фиксируются в BUILD-STATE.md.

Исторический замер: на 24.10.2026 официальный PageSpeed главной: **100 во всех четырёх категориях на mobile и desktop**, после подключения Метрики. [Зафиксированный результат](PERFORMANCE.md), [что сделано и осталось](RECAP.md), [рабочий checkpoint](BUILD-STATE.md).

## Запуск

Node.js 24 (см. `.nvmrc`), npm. Версии зависимостей фиксирует `package-lock.json`.

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 4321
```

Production-сборка и её просмотр:

```sh
npm run check
npm run build
npm run preview -- --host 127.0.0.1 --port 4322
```

Результат сборки — `site/`. Astro генерирует HTML, адаптивные AVIF/WebP и небольшую клиентскую логику; сервер приложения для хостинга не нужен. Внешние шрифты и клиентские UI-фреймворки не загружаются.

Архитектура, найденные пробелы и план спринта: [EGM-аудит](docs/designs/architecture-improvements-20261029.md). Проверка индексации назначена на 10.11.2026; развитие сайта возобновлено 29.10 по поручению пользователя.

## Где менять сайт

- `src/pages/index.astro` — главная страница, блоки и модальные окна.
- `src/components/ProductCard.astro` — карточка пирога и выбор веса.
- `src/data/catalog.ts` — города, ассортимент и предварительные цены.
- `src/scripts/storefront.ts` — подборка, фильтры, сохранение, копирование.
- `src/styles/global.css` — типографика, палитра, адаптивные раскладки.
- `design/assets-source/` — исходные изображения и промпты; [манифест](design/assets-source/manifest.md).
- `src/data/editorial.ts` — городские, продуктовые и информационные страницы.
- `src/pages/sitemap.xml.ts` — карта индексируемых страниц.
- `src/components/InterestForm.astro`, `src/scripts/interest.ts`, `worker/` — форма и сохранение намерения заказать.
- `design/layered-assets-v2/` — слои пирогов, подложки, напитки, логотип и происхождение графики.
- `public/` — favicon, шрифты с лицензиями, robots.txt и социальные изображения.

## Проверка

`npm run check` проверяет Astro и TypeScript. `npm test` запускает 29 Node-тестов, `npm run test:worker` — типы/API/SQLite, `npm run test:browser` после сборки — прежнюю fixture формы и весь путь на готовых страницах Astro в Chrome (320/1280 px). Браузерные тесты перехватывают внешние запросы и сохраняют заявки только в SQLite в памяти. `node scripts/verify-seo.mjs` проверяет страницы, schema, sitemap и локальные ссылки после сборки. `node worker/scripts/verify.mjs` проверяет backend и клиентскую интеграцию. [Визуальная и функциональная QA](design-qa.md) содержит проверенные сценарии и снимки. [Отчёт о скорости](PERFORMANCE.md) отделяет локальные измерения от публичного PageSpeed.

```sh
npm run audit:performance
# или другой уже запущенный production URL
npm run audit:performance -- http://127.0.0.1:4322/
```

Для аудита нужен установленный Chrome. По умолчанию выполняются три mobile-замера и один desktop, каждый в новом процессе и профиле Chrome. `LIGHTHOUSE_MOBILE_RUNS` меняет число mobile-замеров. JSON/HTML каждого запуска, `performance-summary.json` и диапазоны `performance-ranges.json` сохраняются в `qa/` вне Git. Отчёт отдельно показывает расчётный LCP и наблюдаемый LCP с разбивкой задержки; фиксирует версию браузера. Стандартные профили и throttling Lighthouse сохранены. Итоговые показатели зафиксированы в PERFORMANCE.md.

Подмножества шрифтов уже включены в репозиторий. Для пересоздания: установить Python-пакет `fonttools[woff]` в отдельное окружение и выполнить `python scripts/prepare-fonts.py`. Сейчас набор рассчитан на русский интерфейс, цифры, знаки и строчные латинские буквы в домене. При добавлении английских заголовков расширить диапазоны скрипта.

## Публикация

`.github/workflows/pages.yml` на Node.js 24 выполняет `npm ci`, проверку типов, сборку, SEO, Node/Worker/browser-тесты и сверку каталога с рабочим Worker перед публикацией `site/` в GitHub Pages. После deploy повторно проверяются опубликованный `release.json` и `/health` Worker. При несовместимости IndexNow не запускается. Изменение каталога сначала выпускается в Worker; порядок и восстановление пары описаны в [инструкции выпуска](worker/RELEASE.md). Домен — `pirogorsk.ru`, canonical и sitemap уже настроены. После deploy IndexNow проверяет публичные key/manifest и отправляет только изменённые URL, сохраняя успешное состояние в Actions cache. Квитанция — artifact `indexnow-report`; cache miss может повторить начальную отправку. Новая сборка открыта для индексации.

Настройка DNS повторяет схему `/Volumes/DevSim/Projects/MALINA/dns.md`: Cloudflare Free, DNS only, GitHub Pages. Записи и команды проверки — в [DNS.md](DNS.md). Наличие workflow не подтверждает публичную публикацию, выпуск сертификата или результаты PageSpeed на домене.
