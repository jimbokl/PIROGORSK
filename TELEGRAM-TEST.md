## Как измерять

- Зафиксировать фактический канал, дату, цену и доступную статистику просмотра каждого поста. Для дополнительных размещений добавлять отдельную фиксированную UTM-комбинацию в `src/lib/analytics-pageview.ts`, чтобы не смешивать источники.
- Метрика 113767847 → «Метки UTM»: кампания `demand_test_2026_10`, разрез `utm_content`. Основная конверсия — `order_submit`; промежуточные — `catalog_add`, `order_form_open`, `order_form_start`.
- Стоимость перехода = расход / визиты с меткой. Стоимость сохранённого намерения = расход / нетестовые достижения `order_submit`; при нуле достижений стоимость не определена, а не равна нулю.
- Сравнивать релевантность аудиторий и всю воронку; переходы к калькулятору не считать заявками. Количество пользователей, визитов и достижений цели — разные показатели.
- Проверять агрегат подтверждённых записей D1 с исключением трёх QA UUID по ANALYTICS.md. UTM в D1 не сохраняется: распределение по размещениям берётся из Метрики, а не из SQL.
- UTM должна попасть в первый просмотр визита. Собственные проверки не считать результатом рекламы; новый рекламный переход в уже открытой сессии может сохранить прежний источник.

В сборке допускаются только четыре значения полностью совпавшей подготовленной комбинации. Неизвестные/повторяющиеся метки, прочие query-параметры и hash из явного просмотра исключаются. Источник: [правила обработки меток](https://yandex.ru/support/metrica/ru/general/source-tags). Принятие данных счётчиком и реальные визиты в отчёте нужно различать.
