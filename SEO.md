## Что реализовано

- `ContentLayout.astro`: русскоязычный документ, общая навигация, хлебные крошки, подвал, `SeoHead` и существующий компонент `Analytics`.
- `/privacy/` и `/terms/`: сохранены юридические тексты и существующий `Analytics`; заменён только `head` на единый `SeoHead` с `noindex`.
- `SeoHead.astro`: уникальные title/description, canonical без query/hash, Open Graph, Twitter card, robots, шрифты и JSON-LD. Общая иллюстрация `/seo/pirogorsk-og.jpg` — настоящий JPEG размером 1200 × 630, собранный из существующего изображения концепта.
- JSON-LD: `Organization`, `WebSite`, `BreadcrumbList`; на страницах вкусов — `Product` с явным статусом концепта; на заметках — `Article`. Не добавлены вымышленные адреса, даты публикации, отзывы, рейтинги, предложения продажи или наличие.
- `editorial.ts`: тексты, связи страниц и адаптер к текущему `catalog.ts`. Канонический slug берётся из каталога. Для карточек и страниц вкусов используется общий `ProductVisual`, для схемы — изображение из существующего манифеста.
- `sitemap.xml.ts`: статическая карта сайта из того же списка страниц. Старый одноадресный `public/sitemap.xml` заменён endpoint, чтобы пути не расходились.
- `robots.txt`: доступ к сайту, адрес sitemap и Yandex `Clean-param` для `interest` и UTM-параметров.
- `editorial.css`: самостоятельные стили в бумажной, бирюзовой и янтарной палитре; локальные Playfair/Golos; адаптация на 1000, 760 и 420 px; видимый фокус и reduced-motion.

## Контракт с главной страницей

CTA ведут на `/?interest=ID#pirogi`. Это переход к анонимному выбору перед запуском, а не подтверждённый заказ или обещание связаться с посетителем. Окончательные условия, связь и реквизиты пока отложены.

| Тип | Значения `interest` |
| --- | --- |
| Пироги | `meat`, `fish`, `cabbage`, `cheese`, `apple`, `cherry`, `curd` из текущего каталога |
| Города | `city-zelenogradsk`, `city-kaliningrad`, `city-svetlogorsk` |
| Сценарии | `scenario-apartamenty`, `scenario-kompaniya`, `scenario-piknik` |
| Общие страницы | `menu`, `delivery`, `partners`, `about` |
| Заметки | `guide-` + slug заметки |

Машиночитаемый контракт находится в `src/data/editorial-intents.ts`. Это самостоятельный модуль без импортов Astro и изображений: его можно напрямую импортировать в браузерный `storefront.ts`. Экспорты: `editorialCityIntents`, `editorialScenarioIntents`, типы `EditorialCityIntent` и `EditorialScenarioIntent`.

| `interest` | Эффект на главной |
| --- | --- |
| `city-zelenogradsk` | `setCity('Зеленоградск')` |
| `city-kaliningrad` | `setCity('Калининград')` |
| `city-svetlogorsk` | `setCity('Светлогорск')` |

Сценарии — редактируемые примеры предпочтений, а не утверждённые наборы или расчёт порций. Их точный состав показан рядом с кнопкой. Первые два совпадают с существующими примерами `dinner` и `company` на главной. У пикника нет обещания подходящих условий хранения: они ещё не установлены.

**Интеграция в `storefront.ts` выполнена.** Переход с городской страницы меняет город, сценарий объединяет существующую подборку с примером по паре товар/вариант. Повторная загрузка не увеличивает количество; подборка остаётся редактируемой. Переход сам по себе не сохраняет заявку и не вызывает `order_submit`. Адаптив, выбор города и сценарный набор проверены в UI; детали в [design-qa.md](design-qa.md).

`SeoHead` используется как единый источник метатегов. Общий `Analytics` подключён; фактический счётчик **113767847** включён в конфигурацию и проверен на production. Успешная цель вызывается после подтверждённого сохранения в D1, см. [ANALYTICS.md](ANALYTICS.md).

## Основания решений

Городские страницы дают самостоятельные списки вопросов и сценарии, а не только подменяют название города. Это соответствует акценту Google на пользе страниц и предотвращении doorway/scaled-content abuse. Никакой объём текста сам по себе не гарантирует индексацию или ранжирование. [Google: Spam policies](https://developers.google.com/search/docs/essentials/spam-policies).

`Product` без `Offer`, `Review` или `AggregateRating` служит описанием сущности и не удовлетворяет требованиям Google к расширенному товарному сниппету. Поддельные коммерческие данные ради такого сниппета не добавлялись. [Google: Product snippets](https://developers.google.com/search/docs/appearance/structured-data/product-snippet).

Sitemap содержит канонические страницы без параметров. Его наличие помогает обнаружению URL и не гарантирует их индексацию. [Google: Build a sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap). `Sitemap` и `Clean-param` записаны в robots согласно поддерживаемым Яндексом директивам. [Яндекс: robots.txt](https://yandex.ru/support/webmaster/ru/controlling-robot/robots-txt), [Яндекс: Sitemap](https://yandex.ru/support/webmaster/ru/robot-workings/sitemap).

## Проверка и публикация

Команды из корня проекта:

```sh
npm run check
npm run build
node scripts/verify-seo.mjs --scope editorial
node scripts/verify-seo.mjs
```

`verify-seo.mjs` проверяет собранный HTML: метаданные, canonical, один H1, уникальность title/description, JSON-LD, отсутствие неподтверждённых коммерческих сущностей, локальные ссылки и якоря, alt/размеры изображений, sitemap, robots и наличие JPEG. Ограничения длины метаданных в этом скрипте — локальная проверка качества, а не лимиты поисковых систем.

## Расширение 24 октября: полезный инструмент и уведомление об изменениях

`/podbor/`: число гостей × выбранная пользователем порция, округление до реальных вариантов 500 г / 1 кг, выбранные начинки, текущие ориентировочные цены. Это расчёт веса, а не норма питания или обещание готового заказа. Перенос `interest=calculator&items=…&city=…` проверяется по каталогу; параметры не становятся каноническими страницами.

IndexNow: `config/indexnow.json`, публичный key-файл, `scripts/indexnow.mjs`, этап после deploy в Pages CI. SHA-256 HTML канонических страниц из sitemap; общий manifest доступен на домене. Проверка опубликованного ключа/релиза перед одним POST; state обновляется только после 200/202. Неизменные страницы не отправляются повторно. Actions cache может быть вытеснен: тогда следующий запуск заново отправит актуальные URL. Ответ endpoint подтверждает получение уведомления, не индексацию. Доказательство публикации — [QA](qa/planner-indexnow-20261024.md).

Локальная проверка расширения: 55 Astro/TS файлов без ошибок/предупреждений/подсказок, build 31 HTML, SEO 29 URL sitemap / 7 продуктов / 1848 ссылок; 11 Node tests PASS.
